Using the complex professional web application workspace and production design system already created, now create the **interaction architecture and high-fidelity prototype behavior** for the application.

Do **not** redesign the visual system.

Do **not** replace the existing component architecture.

Do **not** create unrelated new screens merely to demonstrate transitions.

Instead, use the existing:

- application shell
- activity rail
- primary sidebar
- editor groups
- tabs
- inspector
- bottom panel
- status bar
- command palette
- menus
- controls
- component variants
- workspace presets
- design tokens

as the foundation for a realistic interactive prototype.

The objective of this pass is to answer:

> How does this workspace actually behave?

The prototype should feel like a real professional desktop application running inside a browser.

The interaction quality should be comparable in sophistication to applications such as:

- VS Code
- Figma
- JetBrains IDEs
- Linear
- Notion
- GitHub
- Slack
- modern database tools
- advanced data-analysis applications
- professional creative applications

Do not copy any one product directly.

Use them only as references for interaction maturity.

The priorities for this pass are:

**state → navigation → focus → selection → commands → panel behavior → resizing → tabs → splitting → docking → drag-and-drop → overlays → keyboard operation → persistence → transitions → accessibility**

# 87. MOTION SYSTEM

Use restrained professional motion.


- subtle translation
- size interpolation

- springy playful motion
- dramatic zoom

# 172. FINAL DESIGN PRINCIPLE

Do not treat the application as a sequence of webpages.

Treat it as a persistent **workspace state machine**.

Conceptually:

```text
Application
    ↓
Persistent Workspace
    ↓
Regions
    ↓
Editor Groups
    ↓
Resources
    ↓
Transient Interaction Layers
```

Navigation should usually modify some part of the persistent workspace rather than replacing the entire application.

The central mental model should be:

> **The workspace persists; tools, resources, panes, and overlays change within it.**

---

# 173. FINAL QUALITY BAR

The resulting prototype should feel believable enough that someone could watch it and infer how the real application would be implemented.

It should demonstrate the interaction sophistication expected from a professional desktop-grade application:

**persistent state, composable panes, command-driven navigation, direct manipulation, keyboard efficiency, discoverability, reversible actions, contextual controls, progressive disclosure, docking, resizing, splitting, focus management, and clear feedback.**

Avoid superficial prototype effects.

Do not prioritize flashy transitions.

Do not create interactions merely because they can animate them.

Every interaction should serve one of these purposes:

- orientation
- navigation
- manipulation
- organization
- feedback
- efficiency
- discoverability
- recovery

The finished result should feel like a **professional browser-based operating environment for complex knowledge work**, not a clickable collection of mockup screens.
