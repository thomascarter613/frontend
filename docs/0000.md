Design a sophisticated, production-quality **desktop-first complex web application workspace UI**.

This is **not a marketing website, dashboard landing page, or simple CRUD admin panel**. It should feel like a professional, information-dense application used for many hours per day, comparable in structural sophistication to **VS Code, Figma, Linear, GitHub, Notion, Slack, JetBrains IDEs, and advanced data/engineering tools**.

The application itself should remain **domain-neutral/general-purpose**, so the resulting shell can later support project management, knowledge management, software development, research, administration, content management, analytics, document editing, or other complex professional workflows.

The primary goal is to design a reusable **“maximum workspace” application shell** composed from clear layout primitives, nested regions, resizable panels, collapsible rails, tabs, panes, inspectors, drawers, overlays, and contextual navigation.

## Overall visual direction

Use a visual language that is:

- premium
- restrained
- highly polished
- modern
- professional
- information-dense without feeling cluttered
- clean and architectural
- optimized for long-duration desktop use
- dark-mode first
- subtle rather than decorative
- built around hierarchy, spacing, alignment, borders, and typography instead of large decorative cards

Avoid:

- oversized dashboard cards
- excessive rounded rectangles
- excessive gradients
- giant headings
- marketing-page aesthetics
- excessive whitespace
- mobile-style controls enlarged for desktop
- playful illustrations
- glassmorphism
- excessive shadows
- excessive color

Think **professional operating environment**, not “SaaS dashboard template.”

```text

│
├── Global Bar
│
├── Workspace Body
│   │
│   ├── Activity Rail

│   │   ├── Tab Strip
│   │   ├── Editor / Content Region
│   │   │   ├── Primary Pane

│   │   └── Bottom Panel
│   │
```

- collapsed

# 21. SPACING AND SIZING

Use a systematic spacing scale.

Favor compact professional density.

Suggested conceptual scale:

```text
2
4
6
8
12
16
20
24
32
```

Typical UI controls:

- 28–32 px compact controls
- 32–36 px standard controls

Avoid excessive 44–56 px control heights throughout the desktop application.

Use relatively tight tree rows, tables, tabs, menus, and property panels.

# 22. TYPOGRAPHY

Use a neutral professional sans-serif similar to:

- Inter
- Geist
- SF Pro
- Segoe UI

Use approximately:

- 12 px metadata
- 13 px dense interface text
- 14 px standard body/UI
- 16 px section titles
- 18–22 px primary contextual headings

Avoid giant typography.

Use typography primarily to establish hierarchy through:

- weight
- contrast
- spacing
- alignment

rather than dramatic size changes.

# 23. COLOR SYSTEM

Design primarily for dark mode.

Use:

- very dark neutral application background
- subtly lighter panels
- restrained borders
- high-legibility primary text
- muted secondary text
- one restrained accent color
- semantic success/warning/error colors

Use accent color sparingly for:

- focus
- selection
- important actions
- active navigation
- status indicators

Avoid filling large surfaces with accent colors.

---

# 24. BORDERS AND SURFACES

Use thin separators and subtle surface differences to establish architecture.

Preferred:

- 1 px separators
- subtle nested surfaces
- very restrained shadow usage
- approximately 4–8 px corner radii

Do not turn every section into a floating rounded card.

Most application regions should visually connect to neighboring regions.

# 31. FINAL DESIGN INTENT

The final result should feel like a **general-purpose professional workstation inside the browser**.

A user should immediately understand that:

- navigation exists at several levels
- multiple resources can remain open simultaneously
- information can be inspected without leaving the current work
- panels can be hidden when unnecessary
- the workspace adapts to different tasks
- advanced users can operate primarily through keyboard shortcuts
- the application could support extremely sophisticated workflows

Think of the application shell as an **operating environment for knowledge work**, rather than a sequence of webpages.

Prioritize:

**information architecture → workspace hierarchy → interaction model → density → component consistency → visual refinement**

over decorative styling.

The UI should be convincing enough to serve as the foundation for a real production-grade application design system.
